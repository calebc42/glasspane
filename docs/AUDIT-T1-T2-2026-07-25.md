# AUDIT — T1 (strict parser) and T2 (editor ownership) against the SPEC (2026-07-25)

Scope: the two architectural items landed earlier today — **T1** (`EbpJson`/`EbpValue` strict
RFC 8259 parser at the frame boundary, `JsonEquality`, the `FrameCodec` integration) and **T2**
(typed editor positions, atomic `edit.apply`, shadow ownership + mirror) — audited back against
`SPEC.md` §4, §6 and §19, the `contract.json` projection, and the `goldens/wire` corpus.

Method: normative text read first as the authority; three adversarial passes (one on the parser
grammar, one on §19 conformance, one differential across the three implementations — the Kotlin
twin driven from the compiled jar, `ebp.el` on real Emacs 30.1, and `validate.py`). Every finding
below was reproduced before being acted on; nothing is asserted from reading alone.

**Result: 9 defects fixed, 6 SPEC amendments (#98–#103 plus the two applied mid-audit), 11
pre-existing defects confirmed and scheduled, 0 findings dismissed as unreproducible.**

## §1 FIXED — conformance defects in T1/T2 code

| # | Rule | Defect | Fix |
|---|---|---|---|
| 1 | §4.1 / RFC 8259 `HEXDIG` | `\u` escapes accepted **372 non-ASCII code points** as hex digits — `Character.digit` is Unicode-aware, so every fullwidth and Indic/Arabic decimal block plus fullwidth `A`–`F` decoded. A peer could spell an escape in fullwidth digits and get content it never encoded, including a bare `U+0022` and a whole surrogate pair that then passed the pairing logic. The org.json class of laxity, inside the parser written to close it. | explicit ASCII table in `hex4` |
| 2 | §19.4 | the **move-only `edit.apply` ignored `seq`** entirely (the text path compared it; the move path never read it), so a caret computed against a superseded document was answered `applied` | `seq` required, stale on mismatch — amendment #98 |
| 3 | §19.3 | a **local edit could be derived from a superseded document**: the view diffs against its own pre-edit text, and between an inbound apply landing and the mirror being adopted that text is stale. `len` is computed from the shadow, so the length equation is satisfied by construction and only the bounds check stood between a racing keystroke and silent corruption | view passes its base; engine refuses a mismatch; existing snap-back re-presents — amendment #100 |
| 4 | §4.2 / §16.1 | **`Number.toInt()` truncated wire positions to 32 bits.** `start: 4294967296` — a legal EBP integer — became `0`, so a splice Emacs asked for *outside* the text was applied at the head of the document and reported `applied`. §16.1: "MUST NOT coerce, clamp, or silently drop an out-of-domain member" | read as `Long`, out-of-domain fails the §19.1 range gate → typed `stale` |
| 5 | §19.1 / §19.4 | **`start + del` overflowed `Int`** and a wrapped sum is not `> n`, so the range guard passed and `substring` got a negative index — an uncaught exception that **closed the transport** over one legal §4.2 integer | `Long` arithmetic in all three bounds checks |
| 6 | §6.2 / §22.3 / amdt #91 | a frame **pipelined behind a malformed one was stranded**: the fault unwound the decode loop, so a request behind the bad frame was never dispatched and never answered until more bytes happened to arrive. If the peer waits on that response, the session deadlocks — the unbounded stall #91 forbids | `feed()` re-enters to drain after a recoverable fault — amendment #102 |
| 7 | §19.3 | **`edit.complete` results were unvalidated**: `optString("prefix")` returned `""` for an *absent* prefix, which `selectCompletion`'s substring check then trivially satisfied — so a malformed result **inserted at the cursor without replacing**, producing a wrong edit (§19.2: "never a wrong edit"). Non-string `prefix` coerced; candidates unchecked | closed-object validation; a non-conforming result is discarded whole |
| 8 | §6.2 (`ebp.el`) | **`Content-Length` matched with `^`/`$`**, which in Emacs match at *line* boundaries — and the header section is split on CRLF only, so `Content-Length: 2\nX: 1` was **accepted as 2** while both other implementations closed. Verified on Emacs 30.1 | `\`` / `\'` string anchors |
| 9 | §4.1 / §6.2 (`validate.py`) | the reference validator **accepted lone surrogate escapes** (`json.loads` preserves them, against §4.1's explicit MUST) and had **no unterminated-header cap**, so the published algorithm buffered without bound against a peer that never sends CRLFCRLF | both checks added |

Defects 1–7 are Kotlin; 8–9 are the reference implementations, found by differential testing and
material because they are what other implementers are told to copy.

## §2 SPEC amendments applied

| # | Section | Hole |
|---|---|---|
| 98 | §19.4 | move-only `edit.apply` never said it *carries* `seq`, nor what happens on mismatch — one reading made "succeeds only at the current sequence" vacuous |
| 99 | §4.2 | the safe-integer range and finiteness were stated as value properties + sender MUST NOTs, with **no receiver duty and no error code**. Now a Parse Error, on the precedent of §4.5's depth limit whose golden already pins that mapping. The underflow/overflow asymmetry is made explicit and deliberate: zero is representable, an infinity is not a value at all |
| 100 | §19.3 | §19.4 gates an inbound apply on shadow equality; §19.3 had **no counterpart for local edits**, and "applied to the shadow immediately" presumes the editing surface and the shadow are one object — false for every renderer that keeps its own copy |
| 101 | §6.2 | the **header line grammar was never defined** for receivers, so three conformant implementations disagreed on identical bytes (space, `0x01`, `0x7f`, bare LF in a name or value) |
| 102 | §6.2 | no rule for a body violating **two faults at once** (implementations diverged purely by detection order), and nothing said a pipelined message must not be stranded across a fault |
| 103 | §19.4 | `max_editor_bytes` bound every *edit* but the **seed** only via a sender MUST NOT — so an over-limit seed was accepted and then every edit in both directions was refused: an editor silently and permanently read-only, with no diagnostic anywhere |

Artifacts: `contract.json` unchanged; new negative golden `22-integer-out-of-range.bin`;
`validate.py` gained the §4.2 numeric check beside its depth and duplicate-member hooks. All three
implementations now replay all 17 wire fixtures identically at every chunking.

## §3 CONFIRMED — pre-existing defects outside T1/T2

Each was reproduced. None is a T1/T2 regression; all predate today. Ranked.

> **RESOLVED 2026-07-25 in `691b052`** (spec side `3c73d75`, amendments #104–#105) — items 1–9
> and 11 are fixed with regression tests; only **item 10** (a P3 ordering nit) is deliberately
> left. Per-item status is marked inline below. Worked before T3 because the P1s all live in the
> seam T3's epoch work touches.

**P1 — wrong data or a dead editor**

1. **[FIXED]** **Phantom sessions from `args`** — `scanSyncedEditors` walks *every* JSON object in a spec, so an
   `{"t":"editor","id":…,"document":…}` inside an action's free-form `args` opens a real session for
   a node that does not exist, consuming a `max_editor_sessions` slot for the connection. A crafted
   `args` can also shadow a real editor's id (last-write-wins over unspecified key order). Fix: walk
   node positions only, and gate on the target profile's advertised types.
2. **[FIXED]** **No session after reconnection** — sessions open only from `surface.update`. If Emacs pushes no
   update after reconnecting (legal — the cached snapshot is unchanged and still rendered per §13.5),
   no `edit.open` is ever sent and the rendered editor is permanently read-only. §19 requires new
   sessions after reconnection. Fix: reconcile from `SurfaceStore` on entering READY.
3. **[FIXED, amdt #104]** **Two surfaces, one `(document, editor_id)`** — the second silently overwrites the first's session
   with no `edit.close`; Emacs then gets `editor-stale` for a session it was never told died, and
   `edit.resync` cannot recover it. Removing *either* surface closes the survivor's session.
4. **[FIXED]** **`pendingEditors` never pruned** (this is **LD-6**, already on the Tier-2 list) — an editor
   accepted during SYNCING and then removed still gets `edit.open` on READY, creating a session no
   close path can reach.
5. **[FIXED]** **Presentation identity ignores `key`** — §16.1 makes `key` the identity when present; the scan
   keys on `id` alone, so a `key` change neither closes the old session nor opens a new one.

**P2**

6. **[FIXED — seam gated]** **Offline editor save reaches the durable queue** — an editor's `on_save` with
   `when_offline: queue|wake` is admitted while not READY, against §19's "MUST NOT create an offline
   … save"; it later replays and overwrites the document with pre-loss text.
7. **[FIXED]** **Synchronized editor + `publish_state: true` creates a persisted draft** — against §19 and
   §13.6's "a synchronized editor never participates in draft reconciliation". Fix in
   `SpecValidator`: do not register a synchronized editor as stateful.
8. **[FIXED, amdt #105]** **Dialogs bypass the editor-session limit entirely** — §19 counts identities across "surface **or
   dialog**" documents; `handleDialogShow` has no count, no limit check, and never opens sessions for
   a dialog's editors, so `editor-session-limit` can never fire from a dialog.
9. **[FIXED]** **§19.5 annotations unvalidated** — negative-length, out-of-range, unsorted and overlapping runs
   reach the host. Already scheduled as the Tier-2 "§19.5 companion half" item, which exists
   precisely to add this bounds checking.

**P3**

10. **[OPEN — deliberate]** **`editor-session-limit` preempts the stale-revision result** — a superseded no-op retry gets a
    hard `1201` where §13.2 requires a benign `{"status":"stale"}`.
11. **[FIXED — deleted]** **`hasDuplicateMembers` is dead but public** and its helper throws raw JVM exceptions
    (`NumberFormatException`, `StringIndexOutOfBounds`) outside the frame taxonomy. Only reachable by
    a direct call; delete or harden.

## §4 VERIFIED CORRECT — recorded so it is not re-litigated

**Parser (T1).** 40,000 valid documents compared value-for-value (UTF-16 units *and* raw IEEE-754
bits) against a C JSON scanner, plus 135 adversarial cases, 20,000 mutations, 200,000 escape cases
and 120,000 random token strings: **zero deviations** beyond defect 1. Nesting rejects at depth 65
with the check firing at ~134 JVM frames (verified on a deliberately-tiny 64 KB stack); no
unchecked index read among all 25 `s[...]` accesses; no `NumberFormatException` reachable; the
number grammar is exact on every edge probed.

**Decoder (LD-21 rewrite).** **86,464 stream × chunking combinations** through the compiled decoder
against a byte-exact port of the pre-rewrite naive decoder and against `ebp.el`: **zero
divergences**. Exhaustive 2-way (57/57) and 3-way (1,653/1,653) splits of a pipelined frame pair all
correct. The `scanned` watermark, `compact()` index shifting, and buffer growth were each traced and
are sound. No unbounded growth (200,000 frames and a slowloris body leave the buffer at 8192), no
infinite loop (every pass advances ≥ 5 octets), no negative-size array operation reachable. The
8,192-octet header cap is byte-exact across all three implementations, terminated and unterminated.

**Editor (T2).** Session IDs, `edit.open` shape, `edit.delta` length equation and ordering,
`edit.caret` semantics and its UTF-16→scalar conversion (clamping, reversed-drag ordering, surrogate
safety), `edit.close`, candidate-selection re-verification, `edit.resync` atomicity and epoch
discard, apply form discrimination, the text-path gates and their pre-mutation atomicity, the
serialization point, the §19.2 closed-session rule, transport-loss teardown, and capability gating —
all verified conforming.

## §5 OPEN QUESTIONS (spec text genuinely undecided — not defects)

1. **Is a node in a non-current view of a multi-view spec "present"?** It is currently counted
   against `max_editor_sessions` and opened. §19 and §4.5 do not resolve it.
2. **`EditorSession.State.STALE` is unreachable.** §19.2's stale transition binds the delta/apply
   *receiver*; an inbound apply failure is answered with a typed stale that explicitly leaves the
   session OPEN. Likely correct by design, but it is dead state.
3. **§4.5's depth check is "before the body is otherwise parsed".** `EbpJson` checks in-parse, which
   bounds the stack at 64 frames (the normative purpose) but parses the first 64 levels first. Same
   taxonomy in every case tested; a literal-reading nit worth a one-line clarification if it recurs.
