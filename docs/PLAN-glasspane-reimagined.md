## §1 Thesis

S8–S11 finished the chrome scaffolding: drawer, enumeration, global-action placement, and system back are now declarations over registry data (PLAN-jetpacs-debt-and-scaffold.md §4, all [LANDED]). PARA (c63935d) then fixed the IA: five tabs, Agenda root, no hub. What remains genuinely open is the **execution substrate**: PARA reaches its IA by editing the 12,128-LOC, 21-module legacy in place and grafting new destination modules onto legacy helpers. This plan proposes the ground-up alternative: **the same ratified IA, reached by v2 code that strangles the legacy destination-by-destination, flag-gated, never breaking the daily driver.** The bet has four legs:

1. **Org files are the stable interface.** Both stacks read and write the same vault through ONE save funnel; the schema (SCHEDULED/DEADLINE, LOGBOOK, SRSITEMS, :CREATED:/:MODIFIED:, datetree, id: links, vulpea index) is untouched — any addition would need a versioned ruling, and this plan makes none.
2. **Verb registration is the atomic cutover point.** Verb names are global and durable (rework I-1); screens are reached by dispatch; owner "glasspane", surface ids, and the reminder-id shape are permanent wire identifiers (SPEC 13.5, I-2). So "cut over Search" = the v2 module registers `search.open` and the legacy module doesn't, selected by a flag at enable time. The frozen names become the strangler's seam instead of its enemy: `heading.tap` flips from legacy detail to v2 detail without any caller knowing.
3. **v2 modules are born clean on the matured seams** the legacy predates: `jetpacs-app-defer-refresh` as the only push API a handler can reach — enforced by a standing lint, not review vigilance (§5.1); the S8 composed drawer, with Glasspane authoring none; the GR-7b registry FAB and `:badge` threading; S10/S11; the reader/editor hosts. The debt classes die by replacement.
4. **Every rung is reversible.** Per-destination phone-settable flags, flip ceremonies with scripted reverses tested in ERT both directions, 3–7-day soaks, deletions citing soaks — the GR/PA discipline at finer grain than PA-3's one big batch.

What this plan deliberately does NOT do: contest the PARA IA (OR-2); rebuild capture/reminders/clock app-side (ratified: jetpacs-org-mode owns them — v2 CONSUMES the org-generic engines); touch the CRDT/OT hard wall, the D-19 widget/tile STOP, paging (D-13), or the embeddable-reader refusal (map OQ6); convert legacy code to new seams when that code is scheduled for demolition (OR-3).
