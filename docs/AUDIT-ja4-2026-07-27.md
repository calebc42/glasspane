# JA-4 adversarial review — the org engine

**Scope:** git range `eec7787..fa901b2` — `emacs/jetpacs-org.el` (1062 lines,
new), `emacs/jetpacs-org-vulpea.el` (141, new), `test/jetpacs-org-test.el`
(663), `test/jetpacs-org-vulpea-test.el` (70), `test/smoke-ja4.el` (240), the
2-line `jetpacs-surfaces.el` reset clause, and the `run-tests.sh` stanzas.

**Method.** Nine dimension finders (grammar security, token/wire boundary,
resolve + file sandbox, org semantics, mutation/save + D2, capture primitives,
cache + bounds, test quality, SPEC/architecture). Every finding was then
attacked by independent refuters on two or three distinct lenses — *code
truth* (prove the code already handles it), *reachability/severity* (prove no
path reaches it, or the severity is inflated), and for P1 claims an
*empirical* lens required to build and run a reproduction. 173 agents, 128
completed, ~10.1M tokens.

**Counts.** 72 findings judged · 48 CONFIRMED · 4 CONTESTED · 16 UNVERIFIED ·
4 REFUTED. After dedup: **12 distinct P1, 21 distinct P2, 9 P3.**

## Honest limits of this review

- **45 agents died on a session usage limit**, including the completeness
  critic, the entire round-2 gap hunt, and the synthesis agent. This document
  was assembled by hand from the workflow journal and per-agent transcripts
  (join by exact prompt-embedded title; zero unmatched verdicts).
- **There was therefore no adversarial completeness pass.** The review is nine
  dimensions deep but has no independent check on what all nine missed.
  Cross-cutting defects (cache × tokens, teardown × timers, the
  `jetpacs-surfaces.el` reset clause × everything) are under-covered by
  construction.
- **16 findings have no verifier vote at all** — their refuters died. They are
  marked `[UNVERIFIED]` throughout and are *unjudged, not validated*. This
  exact failure mode silently corrupted the JA-3 review; it is flagged rather
  than hidden. Of these, the author verified P1-2, P1-11 and P1-12 by hand.
- **The author independently re-verified seven headline P1 claims** with
  runnable reproductions before publication (marked ✓author). The repository
  was checksummed before and after the review: all 92 elisp/shell files are
  byte-identical, tree clean at `fa901b2`.

## Thesis

**The invariant was written down, pinned with a test at one call site, and
then not applied at the others.** This is the JA-1/JA-2 thesis recurring, and
in JA-4 it is nearly the whole story:

| Invariant | Enforced at | Absent at |
|---|---|---|
| remote-before-any-stat | `--check-file` (ERT pins zero stat calls) | `--files-stamp`, `--roots` — both on the hot path |
| depth/node caps | the sexp arm (`--vet-query`) | the token/free-text arm — the arm a search box actually reaches |
| `regexp-quote` on wire text | `heading` term, free-text arm | the `regexp` term |
| log-note flush/cancel | `toggle-todo` | `set-property`, `set-planning` (both reach `org-todo` via `org-entry-put`) |
| no-prompts-in-dispatch (D2) | `jetpacs-with-no-prompts` exists project-wide | `find-file-noselect`, supersession, `org-auto-repeat-maybe`, `basic-save-buffer` |
| `jetpacs-scalar-text` on buffer text | `jetpacs-results.el` | `ref-at-point` `:headline`, typed values, LOGBOOK `:content` |

**Secondary thesis: the module documents invariants it does not enforce.** The
vetter's docstring claims a closed output set of "allowlisted symbols, fresh
strings, integers" (false — text properties smuggle arbitrary graphs, and
arity is never checked); the interpreter's fallthrough calls itself an
"internal invariant" (false — reachable from at least six vetted wire
strings, and it echoes the query); the commentary claims a "14.5-honest"
status map (false — see P1-7, P1-8). Docstrings that assert a guarantee the
code does not provide are worse than silence: they are what the next
implementer will trust.

# P1 — fix before any app tier consumes this module

## Cluster A — wire data does something it must not (SPEC 23.2)

### P1-1 Capture field values and shared text are re-interpreted as org-capture template source ✓author
`emacs/jetpacs-org.el:847` · CONFIRMED (0/3 refute, two dimensions independently)

> **Severity re-rated by Caleb, 2026-07-27 — "RCE" withdrawn as the headline.**
> Sharing to Jetpacs is a deliberate act with knowledge of what is being sent;
> the honest analogy is enabling an .el file, and a warning is a legitimate
> answer for that path. The defect stands, the alarm does not. Two riders were
> accepted onto the record rather than argued: (1) the `capture_fields` vector
> is *not* the share sheet — those values arrive over the wire in reply to a
> dialog Emacs raised, so no user consent attaches to them at all; (2)
> escaping values costs no legitimate capability, because real `%(sexp)` lives
> in the user's own template, never in a field value. Ratified into the SPEC as
> **#139** rather than left as a code opinion: a trust decision must be per
> invocation and informed, and choosing this app as a share destination
> establishes that the user meant to *send* the text here, not to run it —
> with neutralizing the text blessed as the RECOMMENDED cheaper path.

`jetpacs-org-capture-fill` substitutes wire-supplied values *into* the
template and hands the result to `org-capture`, which runs its own placeholder
expansion over the whole text. Substituted values are never escaped, so a
`%(sexp)` inside a phone-typed field — or inside `EXTRA-BODY`, which the
docstring designates as the carrier for text shared from another Android app —
reaches `org-capture-expand-embedded-elisp` → `org-eval` → `eval`. `%[PATH]`
inserts an arbitrary local file into the user's org file.

**Verified by the author:** a value of `hi %(progn (setq vp-sexp-ran t)
"OWNED")` set the variable and wrote `OWNED` into the file; a value of
`%[…/secret.txt]` inserted `TOP-SECRET-PAYLOAD`.

Both capture tests assert only "no `%^` residue", so neither can fail on this.
Green tests, SPEC 23.2 breach, and the most severe finding in the review: any
app that can share text into Jetpacs gets code execution in the user's Emacs.

**Fix:** rewrite `capture-fill` as a single left-to-right pass that emits
literal template text, `""` for leftover `%^X`, and the *escaped* value for
`%?`/`%^{…}` — never re-matching over inserted text. Escape every `%` in
substituted values and in `EXTRA-BODY`. Add ERT asserting `%(error "x")` and
`%[/etc/passwd]` land as inert literals.

### P1-2 A wire-supplied `(regexp …)` reaches the matcher unquoted and unbounded — and no timeout can rescue it ✓author
`emacs/jetpacs-org.el:697` · CONFIRMED (0/3, three dimensions) + one UNVERIFIED duplicate

`regexp` is on the SPEC 23.2 allowlist and `--vet-query` passes its string leaf
through untouched, so a wire string becomes the *pattern* for
`re-search-forward` on every entry of every agenda file. SPEC 23.2 forbids
precisely this ("use a received string as a … pattern that the host
interprets"). Emacs's matcher backtracks, so cost is exponential in body
length.

**Verified by the author, and worse than filed:** the query
`(regexp "\\(a*\\)*b")` against a single 36-character body did not return.
Emacs was killed by an external 40 s bound — and the `(with-timeout 6 …)`
wrapped *around the call inside the same process never fired*, because a
C-level regexp match does not yield to timers. This means a defensive
`with-timeout` in a handler cannot mitigate it. One tap wedges the entire
bridge with no reply, no heartbeat, and no reachable `C-g`.

**Fix:** drop `regexp` from the wire allowlist (`heading` already
`regexp-quote`s and covers the use case), or `regexp-quote` it in the vetter.
A cost bound alone is not sufficient — see the timer finding above.

### P1-3 Reader output escapes the vetter through string TEXT PROPERTIES — caps voided, throwaway-obarray symbols leak ✓author
`emacs/jetpacs-org.el:544` · UNVERIFIED by agents · **verified by the author**

`((stringp x) x)` returns the reader's string object as-is. The `#("str" S E
PLIST)` read syntax hangs an arbitrary object graph off that string: symbols
interned in the *throwaway* obarray, conses of unlimited depth, floats,
vectors, records — none walked, none re-homed, counted as exactly **one** node.

**Verified by the author:** `(todo #("x" 0 1 (ja4-escaped-prop
ja4-escaped-val)))` is accepted; both property symbols fail
`(eq s (intern-soft (symbol-name s)))`, i.e. they are live references into an
obarray the design intends to discard — defeating the entire purpose of the
isolated read. A 300-deep nested structure smuggled inside a text property
passes a depth cap of 8.

**Fix:** `(substring-no-properties x)` plus a length bound in the vetter — which
also makes the docstring's "fresh strings" claim true. Strengthen the obarray
test to assert no symbol reachable from the returned tree fails `intern-soft`
identity.

### P1-4 The token/free-text arm has no node cap at all ✓author
`emacs/jetpacs-org.el:584` · UNVERIFIED by agents · **verified by the author**

The 128-node/8-depth caps live inside `--vet-query`, i.e. only on the sexp arm.
The token/free-text arm — the arm a phone search box actually reaches — maps
tokens one-to-one into clauses with no count, length, or cost bound.

**Verified by the author:** one query string produced **3000 clauses** against
a sexp-arm cap of 128. The finder measured 5000 clauses = 9.8 s and 20000 =
31 s on a 200-heading fixture; at the 4 MiB wire body limit this extrapolates
to ~40 minutes of uninterruptible blocking. Empty tokens (`""`) become
`(regexp "")`, which matches everything, so `cl-every` never short-circuits.

**Fix:** move the node cap into `jetpacs-org-parse-query` so it governs both
arms; refuse over-long query strings before tokenizing; drop empty tokens.

## Cluster B — D2: blocking and modal prompts inside the dispatch extent

### P1-5 A missing `org-agenda-files` entry drives every query into `read-char-exclusive` ✓author
`emacs/jetpacs-org.el:717` · CONFIRMED (0/3)

`org-map-entries … 'agenda` runs `org-agenda-prepare-buffers` →
`org-check-agenda-file`, which for any non-existent entry messages the absolute
path and calls `read-char-exclusive`. `org-agenda-skip-unavailable-files`
defaults to nil. **Verified by the author:** with one vanished agenda file the
query did not return. A deleted or renamed org file — or an unmounted drive —
blocks the whole Emacs process, socket filter included.

**Fix:** pass an existence-filtered explicit file list (the module already has
that predicate in `--files-stamp`), and belt-and-braces let-bind
`org-agenda-skip-unavailable-files` to t.

### P1-6 The resolve/mutation spine reaches at least four modal prompts
`emacs/jetpacs-org.el:234, 248, 389, 418` · CONFIRMED (0/3) + 2 UNVERIFIED

Four distinct paths, none guarded:
1. `find-file-noselect` is called with **no NOWARN** at both open sites →
   changed-on-disk `yes-or-no-p`, large-file query, unsafe-local-variables
   confirm. It also emits two absolute-path messages into `*Messages*`, which
   the base app offers to the device (23.3 leak).
2. `ask-user-about-supersession-threat` fires on the body's first modification
   when the file drifted — it calls `discard-input` (eating the desktop user's
   typeahead) then loops on `read-char-choice`. `--save-now`'s own supersession
   refusal is what *creates* this state.
3. `org-auto-repeat-maybe` raises `y-or-n-p` for a catch-up (`++`) repeater
   more than 10 intervals behind. Declining leaves the file **half-repeated**:
   SCHEDULED shifted 9 of 30 steps, `LAST_REPEAT` written, state inconsistent.
4. `basic-save-buffer` has two more prompts the gate misses (write-protected;
   missing final newline under `require-final-newline`).

Inside a handler these become `inhibited-interaction` → the tap is answered
`rejected` and permanently discarded. From a flow continuation or a timer they
hang the process filter outright.

**Fix:** pass NOWARN at both opens; clamp the whole spine
(`query-about-changed-file` nil, `large-file-warning-threshold` nil,
`enable-local-variables :safe`); rebind `ask-user-about-supersession-threat`
and `y-or-n-p` to signal `jetpacs-org-refused` so a drift becomes a *status*,
not a question. Stop claiming in the docstring that the log note is the only
interactive hazard.

### P1-7 The remote-before-stat guard is applied to the ref but not to the roots or the cache stamp
`emacs/jetpacs-org.el:79, 131` · CONFIRMED (0/3 and 0/2)

`--check-file` correctly refuses remote names before any stat, with a comment
explaining that *the stat IS the connection* — and an ERT pinning zero
stat-family calls. Then `--roots` calls `(org-agenda-files)` +
`file-directory-p`/`file-truename` over every agenda entry with no remote
check, and `--files-stamp` calls `file-exists-p`/`file-truename`/
`file-attributes` on every entry on **every cache-key computation**.

One remote agenda file therefore makes a TRAMP connection attempt on every ref
resolve, every token mint, and every query, inside the socket filter —
`tramp-connection-timeout` is 60 s. If it fails, the allowlist collapses to nil
and *every* heading is refused `outside-roots` permanently.

**Fix:** one `jetpacs-org--local-agenda-files` helper that filters
`file-remote-p` on raw names, used by both; do not let an empty root set mean
"refuse everything" without saying so.

## Cluster C — the token and status contract

### P1-8 A partially-failed mint orphans tokens past both sweeps ✓author
`emacs/jetpacs-org.el:310` · CONFIRMED (0/3, three dimensions)

`ref-tokens` performs the replace sweep and starts `puthash`ing new tokens
*before* validating every ref. If ref N fails `--check-file`, the signal escapes
with tokens 1..N-1 in `--tokens` but `--token-sets` never updated. Those tokens
are unreachable by the replace sweep, unreachable by owner teardown, never
counted against the 32-set cap, and removable only by `jetpacs-org-reset`.

**Verified by the author:** after a failed mint, `jetpacs-org--on-teardown`
left a live token in the table. The live generation is also destroyed, so the
surface's existing tokens all go stale at once.

**Fix:** validate every ref in a first pass, then sweep and install both tables
together — an all-or-nothing mint.

### P1-9 `resolve-ref` guesses where SPEC 14.5 says it MUST answer `stale` — the wrong heading is mutated
`emacs/jetpacs-org.el:247` · CONFIRMED (0/3)

Two arms bind a marker in cases the ladder itself knows are ambiguous:
- Step 4's headline scan takes the **first** title match; its own docstring says
  "ambiguous by construction among duplicate titles".
- Step 3's drift check short-circuits to *true* when `:headline` is empty or
  nil — and `ref-at-point` produces `:headline ""` for any heading with no
  title text. **The gate falls open in exactly the case it exists to gate**
  (defect shape (b)).

Failure: two `* TODO Review` headings; a token minted for the second; the
desktop user edits the first; the queued tap resolves to heading #1, marks the
heading the user did **not** tap as DONE, writes the file, and answers
`accepted` with no diagnostic anywhere.

**Fix:** step 4 collects *all* matches and signals `jetpacs-org-unresolved`
unless exactly one survives. Step 3's headline check becomes mandatory. No SPEC
change needed — §14.5 already mandates `stale` for ambiguous context; it is the
plan's "content drift → stale" claim that is currently false.

### P1-10 `jetpacs-org-refused → rejected` is not SPEC-legal: a transient condition permanently deletes a durable record
`emacs/jetpacs-org.el:97` · CONFIRMED (0/3)

SPEC 14.4 defines `rejected` as "permanently invalid" with Companion
disposition **delete the durable record**. Two of four refusal reasons are not
permanent: `unreadable` is an I/O condition, and `outside-roots` depends on
`jetpacs-org-roots`/`org-directory`/`org-agenda-files`, all mutable at runtime.

Failure: an org vault on removable storage or a gvfs mount. The user marks
three headings DONE offline; the Companion durably queues them; on reconnect
the mount is not ready, all three are answered `rejected`, and the Companion
**deletes all three records**. The mount returns seconds later. Silent loss of
durably-admitted user intent.

**Fix:** split the condition — `refused` (→ `rejected`) keeps `not-absolute`
and `remote`; a new `jetpacs-org-unavailable` (→ `1500 event-retry`) takes
`unreadable` and an empty root set. A file that vanished should raise
`unresolved` (→ `stale`), not a policy refusal. Ship a
`jetpacs-org-refusal-disposition` helper so handler authors get the mapping for
free. **No SPEC change needed** — §14.4 already names `1500 event-retry` as the
remedy; the module contradicts a clause that is already correct.

## Cluster D — the cache serves answers about a file it did not read

### P1-11 Freshness is keyed on the DISK mtime while every cached value comes from the BUFFER
`emacs/jetpacs-org.el:116` · CONFIRMED (0/3)

`--files-stamp` derives the entire freshness signal from `file-attributes`, but
every cached value is produced by `org-map-entries`/`ref-at-point` reading the
*buffer*. An org buffer modified in Emacs and not yet written — the normal
state of a working buffer, and precisely the state `with-mutation` deliberately
leaves for 0.5 s — does not move the key at all.

Combined with P1-9's first-match-wins scan, the phone re-renders from stale
cached positions and a tap then mutates the **wrong heading**.

**Fix:** fold buffer state into the stamp — contribute
`buffer-chars-modified-tick` for any file with a live visiting buffer. One
cheap call per open file.

### P1-12 The query cache key omits ACTION — a second caller silently receives the first caller's payload ✓author
`emacs/jetpacs-org.el:729` · CONFIRMED (0/2, three dimensions)

`jetpacs-org-query` keys on (date, stamp, namespace, tree) but the cached value
is `(mapcar ACTION matches)`. **Verified by the author:** two queries with the
same namespace and tree but different actions returned `(FIRST-ACTION)` both
times.

This is a D-4 boundary breach, not merely a cache bug: JA-5 will naturally call
the same tree once for display titles and once for refs to tokenize. Whichever
runs second gets the other's list — so `ref-tokens` can receive bare strings,
and its per-ref policy check is *skipped* because `(plist-get "Alpha" :file)`
returns nil rather than erroring. Absolute-path ref plists can flow to a
consumer that asked for display text.

Separately, `format "%S"` honours `print-length`/`print-level`, so a caller
with those set can collide two different trees.

**Fix:** require an explicit caller-supplied key alongside the closure (a
closure has no stable printed identity), bind the printer variables
explicitly, and make `ref-tokens` reject a non-plist ref instead of silently
tokenizing it.

# P2 — 21 distinct (grouped)

**Query semantics (org disagreement).** Every query includes `:ARCHIVE:` and
COMMENT subtrees — `org-map-entries` with an empty SKIP sets both skip flags
nil while org's own defaults are t · the `tags` term passes `LOCAL=t`, so tag
**inheritance and `#+FILETAGS` are invisible** · scheduled/deadline windows
compare against the repeater's *base* date, so repeating tasks and habits never
match `:on`/`:from` (CONTESTED — the code-truth refuter argues org's agenda
default is also base-date; the reachability refuter attacked it and reports the
finding got *stronger*; needs a ruling) · `priority`/`level` read raw heading
syntax rather than the normalized entry property, so an entry with no cookie is
excluded from every priority term (CONTESTED — arguably intended).

**The vetter's arity hole.** `--vet-query` checks head *names* but never arity
or leaf type, while `--matches-p` pcases on exact arity — so at least six
vetted wire strings reach the "internal invariant" fallthrough, which raises
`user-error` **and echoes the query** (23.3). Fix once with an arity+type
schema per allowlisted head; this closes the fallthrough, the echo, and the
`property`-head hole below.

**The `property` head takes an unconstrained NAME**, so the wire can read org's
special properties — including `FILE`, the absolute path the token model exists
to hide. (UNVERIFIED.)

**Token table.** The set-cap guard uses the set's *value* as its existence test,
so a set that last rendered empty counts as a new set and spuriously errors at
the 32-set ceiling — a view that legitimately renders "nothing scheduled today"
wedges permanently · tokens are not opaque: a shared per-session nonce plus a
**global monotonic counter** lets a device enumerate an owner's unrendered refs
· minting stat-storms the filesystem (roots recomputed per ref: measured 111k
`file-truename` calls for one 512-ref mint, ~1.8 s blocked in the dispatch
extent) · `token-ref` returns nil on a nil owner while `ref-tokens` signals —
a permanent stale loop with no diagnostic.

**Cache.** Unbounded growth: every distinct stamp mints a new key generation and
nothing evicts; the key includes wire-supplied text, so N hostile queries retain
N entries for the process lifetime.

**Capture and primitives.** `with-timeout`'s arm is a **silent no-op** — a stuck
capture returns normally, so a handler answers `accepted` while nothing was
written (this is the "capture that vanished" the port claims to have fixed),
plus 30 s of blocking and a leaked `*Capture*` buffer · `capture-fill`
disagrees with org's `%^{…}` grammar: key-suffix forms (`%^{Effort}p`) leave a
stray letter, and completion defaults insert the whole option list · a `%\N`
back-reference in a user template makes **every** phone capture fail with
`wrong-type-argument stringp nil` · 2-element prefix-group entries in
`org-capture-templates` are exposed to the phone as pickable templates and
crash `capture-run` · `set-repeater` searches case-folded and unanchored, so it
edits timestamps in the PROPERTIES or LOGBOOK drawer, and it destroys a habit's
max-interval (`<… Sat .+1d/3d>` → `<… Sat/3d>`) · `clocked-in-p` returns a
false positive in a narrowed buffer (`goto-char` clamps).

**Mutation spine.** The log-note flush/cancel lives only in `toggle-todo`;
`set-property` and `set-planning` reach `org-todo`/`org-schedule` through
`org-entry-put`'s special-property branches with no settle (UNVERIFIED) · the
settle block is **not** `unwind-protect`ed, so any signal out of `org-todo`
leaves org's note state poisoned for the desktop user (UNVERIFIED) ·
`with-mutation` puts `cache-invalidate` and `defer-save` inside the protected
form, not the cleanup, so a body that edits and then signals leaves a modified
buffer with no save armed and a cache serving pre-edit data (UNVERIFIED) ·
returning `accepted` for an effect owned by a volatile idle timer is a direct
SPEC 14.4 violation ("returning `accepted` merely because a volatile callback
was scheduled is not conforming") — there is no `kill-emacs-hook` flush, so
the edit is lost if Emacs exits within the debounce window (UNVERIFIED).

**Boundary.** `ref-at-point` copies the headline out of the buffer unsanitized;
a raw octet makes the whole surface unpushable (SPEC 4.1, the JA-3 lesson
un-applied). The module states **no 4.1 contract at its boundary** at all —
`:headline`, typed values, LOGBOOK `:content` and query results are all raw
buffer text handed to a consumer that will put them on the wire.

**Seam.** `jetpacs-org-file-save-function` is a documented app seam that **no
code path calls** — `with-mutation` calls `defer-save` directly (CONTESTED on
severity only; both refuters confirm the seam is dead).

**A relative entry in `jetpacs-org-roots` resolves against the ambient
`default-directory`** — inside the process filter that is whatever buffer
happens to be current, so the sandbox moves.

Three tests do not test what they are named for, and this matters because the
rung was declared green on them:

# Proposed SPEC amendments

Most findings need **no** SPEC change — §14.4, §14.5, §23.2 and §23.3 already
state the rules the code breaks. Two genuine gaps:

**#137 — §23.2 (cross-ref §22.3):** *A deliberately exposed search grammar is
still a received pattern.* §23.2's clauses read as rules about *accidental*
interpretation (eval, read). An allowlisted grammar that intentionally exposes
a `regexp` term is the same hazard wearing a design: the receiver hands
peer-controlled text to a backtracking matcher. Ratify that a received string
may reach a regexp engine only after `regexp-quote`, or through a bounded,
cost-vetted compiler — and note that an in-process `with-timeout` is **not** a
valid mitigation, since a C-level match does not yield to timers (measured).

**#138 — §4.5 / §23.5:** *Receiver-side interpretation and retained state must
be bounded independently of the body limit.* 4 MiB of well-formed JSON is cheap
to parse and catastrophic to interpret (~40 minutes for one query), and a memo
keyed on peer text grows for the process lifetime. The aggregate-budget genre
currently governs only outbound surface specs.
