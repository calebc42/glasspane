#+title: Glasspane Navigation Contract

* The rule

Glasspane has one document presentation route. Features may discover a
document in different ways, but they do not get to invent a destination UI.

A heading card does not open a document at all. Tapping a card on Agenda,
Projects, an Area, Search, a saved View or a Connections row pushes the
heading's own page (=heading.tap=, the =glasspane-detail= screen) on the
surface the tap came from, exactly as a note row does in Orgzly. The page's
*Open in file* is the one place a heading becomes a document:

#+begin_example
Project / Agenda / Area / Search / Note card
        |
        | durable Glasspane heading token
        v
  heading.tap ----> glasspane-detail (same surface, Back = where you were)
        |
        | Open in file
        v
  heading.visit -- resolve immediately --> (path, position) --+
                                                               |
Resource / Archive / Area file row / breadcrumb                |
        | validated path                                       v
        +--> glasspane.document.open -----------------> open-document
                                                               |
                                                               v
                app:jetpacs.files / edit / Glasspane Org reader
                staged files-return / glasspane.files.return
#+end_example

* Stack shape

Five peers (Agenda, Projects, Areas, Resources, Review) plus the
drawer-only Archive switch through =glasspane-ui-open-destination=: the
stack truncates to the pinned Agenda root and the peer is pushed above
it. A peer draws no Back arrow but declares =:on-back= to the root
(=glasspane-ui-peer-on-back=), because a scaffold with neither lets the
Companion finish the Activity.

Everything below a peer is a child push (=glasspane-ui-push-child=): an
Area drill sits above the Areas list, the detail page above whatever
listed it, Search above whatever had focus. Chrome keeps three screens
with the root pinned, so a third level evicts the screen above the root.
A child therefore computes its Back with =glasspane-ui-parent-back=
(the drill reopens the Areas list when the list was evicted) or
=glasspane-ui-route-back= (Search and detail reopen the selected
destination when it was evicted); the switch chrome hands over is used
whenever the parent is still beneath.

Every list row carries a =:key= minted by =glasspane-ui-item-key= or an
opaque path id, never a readable path: the Companion restores a lazy
column's scroll position by its children's keys. Every destination
screen carries =:on-refresh= (=glasspane.refresh=), which drops the Org
memo table and re-renders.

On a medium or expanded window with a Companion that draws
=pane_scaffold=, Agenda, Projects and every Area drill lay their list beside
a heading pane (=glasspane-detail-with-pane=).  =heading.tap= from one of
those screens selects instead of pushing: the ref is stored per screen
(=glasspane-ui-pane-select=, Emacs-side only) and only the top screen
rebuilds.  The pane's close button and the screen's back gesture send
=glasspane.pane.close=; deleting, refiling or archiving the shown heading
closes the pane.  Search, saved Views and every compact window keep the
pushed detail screen.  The pane mints its tokens in distinct sets
(=glasspane-detail--set-suffix=) so a pushed detail above it cannot sweep
them.

Resources is a Glasspane screen over the agenda-scope files; only its
*Browse in Files* action (=resources.browse=) hands the whole vault to
Files, with the capture FAB and the return to this untouched stack.

The convergence point is =glasspane-navigation-open-document= in
=glasspane-navigation.el=. It fixes all presentation choices:

- the owning surface is =app:jetpacs.files=;
- regular files use Files' one shared =edit= document host;
- Org files start in Glasspane's tree reader with stale filters cleared;
- =files-return= is staged below the document; and
- Back uses =glasspane.files.return= to restore Glasspane's untouched stack.

That last property is important. Opening a Project TODO must not turn the
current route into Resources, and opening a Resource must not manufacture a
Project detail stack. Both temporarily use the same Files host, then return to
the place from which the user left.

* Why two opening actions remain

The actions before the convergence point express authority, not presentation.

| Entry point | Wire action | Authority | Stale behavior |
|-------------+-------------+-----------+----------------|
| Detail page *Open in file*, reader heading source | =heading.visit= | app-scoped =ebp-org= token | token resolution returns =stale= after the rendered identity expires |
| Agenda / Projects / Area / Search / View / Notes card | =heading.tap= (not a document route: pushes the detail page on the tapped surface) | app-scoped =ebp-org= token | an expired token answers =stale= |
| Resources row (=glasspane-resources-row=) | =glasspane.document.open= | path | Files canonicalizes and revalidates the path against its effective roots |
| Resource row, file breadcrumb | =glasspane.document.open= | path | Files canonicalizes and revalidates the path against its effective roots |
| Area drill file row, Archive row (=glasspane-areas--file-row=, =glasspane-resources-archive-row=) | =glasspane.document.open= | path | as above; an archive path is the sibling =FILE.org_archive= |
| Area declaring-note card (=glasspane-areas--declaring-card=) | =heading.tap= | app-scoped =ebp-org= token | as the card row above |
| Outline link span (=glasspane-org-reader--emphasis-spans=), Properties link button (=glasspane-detail--property-link-action=) | =jetpacs.org.follow= (foundation) | exposed buffer position; Org itself resolves the destination | an unexposed position is =rejected=; a tick or link-syntax mismatch returns =stale=; =glasspane-org-reader--present-link-destination= then sends a file-backed destination to =glasspane-navigation-open-document=, acknowledges an external target, and reports a refused path rather than drilling |
| (foundation twin, not emitted by Glasspane) =jetpacs-files-document-action= | =jetpacs.files.open-document= | path, optional position | the same Files revalidation; the ownerless verb any app may render.  Glasspane keeps =glasspane.document.open= because its handler also prepares the reader landing (=glasspane-org-reader-prepare-landing=) |

A rendered link carries a buffer position only because Org must parse the
link at tap time; the exposure table and modification tick make that position
a bounded snapshot, and Org's own resolver produces the destination.  The
follow verb is the foundation's; Glasspane adds
=glasspane-org-reader--present-link-destination= to
=jetpacs-org-render-follow-functions= for links followed on its surface, from
a dialog, or in the document Files shows.  It converges on the same document
route, so a linked heading gets the same reader, staged Back screen, and
return action as a Project row.  The device never sends a link text to
open: a Properties link was once a raw =org.link.open= string, which also
pushed a screen past this route.

A heading card must not serialize a raw buffer position: edits can move the
heading between render and tap. A file row must not mint an imaginary heading
identity. Their handlers therefore remain small adapters and both call the
same presenter after validation.

The compatibility names older versions emitted (=detail.open-file=,
=resources.open-file=, =resources.return=, =tasks.open=, =views.hub=,
=journal.capture=, =files.properties.*=) were retired on 2026-10-24. A tap
from a specification cached before then is refused rather than redirected.

* Adding an entry point

1. Decide what durable authority the row actually has.
2. For a heading token, render
   =glasspane-navigation-heading-action=. For a path, render
   =glasspane-navigation-document-action=.
3. If a new authority type is genuinely necessary, validate and resolve it in
   a tiny handler, producing only =(path, optional-position)=, then call
   =glasspane-navigation-open-document=.
4. Do not call =jetpacs-files-open-path=, =jetpacs-navigate-buffer=, or
   =jetpacs.files.open= from the feature.
5. Add the builder and adapter to
   =test/glasspane-navigation-test.el=.

The test suite also scans the flat applet sources and fails if any file other
than =glasspane-navigation.el= calls =jetpacs-files-open-path=. This is the
mechanical guard against presentation policy spreading back into features.

The historical
=poc/v3-pre-split:test/glasspane-para-test.el::glasspane-para-pa3c-mark-position-navigation-family=
still describes the retired Glasspane-local =jetpacs-navigate-buffer= drill.
Glasspane is downstream now; that upstream POC test is migration evidence, not
the applet's current contract. Do not restore its expectation. The owned suite
in this directory supersedes it.

* What the tooling can and cannot prove

The static applet MCP inventories owners, actions, roots, dependencies,
docstrings, and lifecycle symmetry without executing Glasspane. That catches
many structural mistakes, but two individually valid handlers can still
choose different screens. The focused ERT suite supplies that semantic proof:
it evaluates the real builders, verifies both authority adapters converge, and
pins the exact Files/reader/Back policy.

The trusted runtime MCP then loads this explicitly trusted applet and checks
that selected builders return the same canonical IR twice in the same bounded
context. Deterministic rendering makes a difference inspectable; it does not
replace the navigation contract or the device flow that proves native Back and
chrome behavior.

* Development and deployment

This source checkout contains older neighboring =.elc= artifacts. They are not
source authority and applet work must not overwrite them incidentally. A
development load must bind =load-prefer-newer= to non-nil, as the focused ERT
and trusted-runtime commands do. A packaged deployment must omit old bytecode
or compile the current =.el= bundle afresh; otherwise ordinary =require= will
load the stale entry file and the new navigation module will not exist in that
session.
