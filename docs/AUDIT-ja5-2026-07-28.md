## 1. Confirmed and fixed

The 13 confirmed findings collapse to seven distinct defects; three more
(the dead-skeptic set) were hand-verified real and fixed in the same
batch.  Fix commit: `2425629`.

**P1-1 — the Schedule arm could never write.** `(upcase "schedule")` is
`"SCHEDULE"`; the engine keys on `"SCHEDULED"`, so seeding read a
nonexistent property and every save/clear signaled `user-error` into the
"That did not work" snackbar.  Deadline worked only by the accident of
its spelling.  Found independently by three dimensions.  *Fix: explicit
value→which map.  Regression: `schedule-arm-maps-scheduled`.*

**P1-2 — the footnote Copy builtin was gated against the wrong
profile.** `jetpacs-builtin-advertised-p` with no target defaults to
`:app`; SPEC 18.1 validates a dialog spec against the DIALOG profile,
whose reference set is only `dialog.submit`/`dialog.dismiss` — so every
footnote WITH a definition shipped a builtin the Companion 1201s, and
the callback swallowed the error: a silently dead tap in the feature's
primary case, masked because definition-less footnotes worked.  The ERT
profile pin could not catch it (the stub profiles carried no `:builtins`
member, so the button was never built under test).  *Fix: gate on
`:dialog`; the button degrades away.  Regression:
`copy-button-needs-dialog-profile` (stub profiles now carry builtins).*

**P1-3 — a captured device field reached the org file unvalidated
(23.1).** `--ts-rep` validated the repeater type and count but
concatenated the UNIT verbatim; a crafted `:ts-rep-unit` of
`"w>\n* EVIL"` smuggled arbitrary text — headings included — into the
buffer at save.  *Fix: one shape table
(`jetpacs-org-dialogs--ts-field-shapes`) guards every captured ts field
at both merge points (conclude AND pick); a failing member is dropped.
Regression: `rep-unit-injection-blocked`.*

**P2-4 — table-cell spans never spent the span aggregate.** The
reference Companion counts every RichSpan — table-cell spans included —
against `max_rich_spans`; the sender spent cells and bytes only, so
prose near the cap plus a table passed every local gate and 1201'd the
whole push on device.  *Fix: `--emit-native-p` spends CELLS against the
span allowance too.  Regression: `table-spends-span-aggregate`.*

**P2-5 — legal org silently killed the timestamp dialog.** Org accepts
1-digit hours and hourly repeaters; `time_button` rejects `"9:30"` and
the unit enum rejects `"h"`, so the spec build signaled inside the
`run-at-time` continuation after the tap had answered `accepted` — no
dialog, no snackbar, a leaked session.  Worse, the documented
"delay cookies are ignored" was actually "destroyed on save", and /max
habit tails likewise.  *Fix: seeds are node-legal (zero-padded times;
unsupported repeaters seed `none`), and the unrepresentable cookies
(`:rep-raw`, `:rep-tail`, `:delay`) ride the session and are re-appended
by the body save — the editor never destroys what it cannot show.
Regressions: `ts-seed-shapes`, `ts-seed-legal-and-preserving`.*

**P2-6 — inline footnotes showed the wrapper, not the definition.**
`org-footnote-at-reference-p`'s `nth 3` IS the inline definition string
(emacs-30.1 org-footnote.el:199); reading it as a boolean and
substringing the reference bounds rendered `[fn:note:…]` verbatim — and
Copy copied it.  *Fix: read `nth 3` as the definition.  Regression:
`inline-footnote-shows-definition`.*

**P2-7 — a rotted heading pos struck a different heading (14.5).**
`--ref-at` ran `org-back-to-heading` from the armed pos, so a pos that
drifted into another subtree's body resolved to THAT subtree — every
sheet arm and the minted Archive token targeted the wrong heading, with
only the sheet title as a clue.  The checkbox and timestamp arms already
re-verified; the heading arm did not.  *Fix: the pos must still sit ON a
heading line, else "No heading there".  Regression:
`sheet-refuses-rotted-pos`.*

**P2-8 (dead-skeptic, hand-verified) — Archive's feedback targeted the
shell default.** The Archive button concludes in DIALOG context — the
event carries `:dialog_id` and no `:surface` (14.4 exclusive contexts) —
so `--notify`/`--refresh` resolved nil to the default surface while the
user's screen kept showing the archived subtree.  *Fix: the sheet slot
carries its opening params; the handler falls back to them.  Regression:
`archive-dialog-context-surface`.*

**P2-9 (dead-skeptic, hand-verified) — the footnote drill landed on the
wrong surface.** `jetpacs-navigate-buffer` from a bare timer with no
SURFACE resolves to the shell default, not the tapped surface.  *Fix:
pass the tap's surface.  Regression:
`footnote-drill-targets-tap-surface`.*

**P2-10 (dead-skeptic, hand-verified) — picks wiped repeater edits
(14.1).** The pick descriptors captured nothing, so the re-present
reseeded the repeater fields from the session, reverting uncommitted
edits.  The module commentary's claim that picks "cannot capture"
misread 17.4 — the *buttons* are not stateful, but `capture_fields` on
the pick descriptor may name the stateful repeater trio.  *Fix: both
picks capture the trio; the handler shape-checks and merges before
re-presenting.  Regression: `pick-preserves-repeater-edits` (also pins
the `capture_fields` sets on the descriptors).*

## 2. Refuted (recorded so they are not re-found)

- **Habit Done's durable descriptor vs per-build tokens** — refuted 2:1:
  the dedupe key and queue semantics are correct against a token that
  outlives the screen *within* the session; the replace sweep happens at
  re-BUILD, by which time a queued Done has either replayed or been
  superseded by a fresh descriptor.  A token swept mid-queue answers
  `stale`, which is the honest outcome.
- **Log-note 2-space indent forges LOGBOOK/CLOCK lines** — refuted 3:0:
  the note text is scalar-scrubbed and newline-indented under a `- `
  list item; a crafted line cannot terminate the drawer (`:END:` must
  sit at column 0 modulo drawer indent rules the parse enforces), and
  the engine's LOGBOOK parser reads the result as one note entry.

## 4. What the review says about the process

The three headline P1s share one shape: **the invariant lived at one
call site and the code path that needed it was a sibling** — the unit
validated nowhere while type/count were; the builtin gate present but
aimed at the wrong profile; the re-verify discipline applied by two arms
out of three.  This is the JA-1/JA-2/JA-4/JA-6 thesis, fifth recurrence.
The other lesson is older still: the ERT profile pins passed while the
defective node was never built under test, because the stub client
lacked the `:builtins` member — a test can only refuse what its fixture
can express.
